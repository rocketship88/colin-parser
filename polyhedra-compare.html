End of the filechanged−0 +19

The new procs are compiled here, once, by one Calc::transformProcs call listing each by name. Then : and = are removed, so any Calc code that was missed fails with an error naming the proc and line instead of silently using the slow path. If all the procs were in a namespace, one wild-card call such as Calc::transformProcs ::poly::* could compile them all, since a proc with no Calc code in it is left unchanged. Calls between those procs would keep their plain names, since Calc looks a function up in the namespace of the proc it is compiling, then in the global namespace.
